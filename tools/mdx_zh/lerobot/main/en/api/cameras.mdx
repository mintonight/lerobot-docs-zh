# 相机

相机提供 policy 所看到的图像 observation。每个后端——OpenCV、Intel RealSense、Reachy 2——都
实现了 `Camera` 接口，因此更换硬件不会改变读取帧的代码。

有关选择与配置相机的说明，请参阅 [相机指南](../cameras)、
以及针对核心集合之外设备的[第三方相机与传感器](../third_party_sensors)。

<Docstring name={"async_read"} anchor={"lerobot.cameras.Camera.async_read"} source={"https://github.com/huggingface/lerobot/blob/main/src/lerobot/cameras/camera.py#L121"} parameters={[{"name": "timeout_ms", "val": ": float = Ellipsis"}]}>
<paramsdesc>- **timeout_ms** -- 等待新帧的最长时间（毫秒）。
  默认为 200ms（0.2s）。</paramsdesc><rettype>np.ndarray</rettype><retdesc> 捕获的帧，以 numpy 数组形式返回。</retdesc><raises>- 如果在 `timeout_ms` 内没有新帧到达，则抛出 ``TimeoutError``。</raises><raisederrors>``TimeoutError``</raisederrors></Docstring>
返回最新的新帧。

此方法获取后台线程捕获的最新帧。
如果缓冲区中已有新帧可用（自上次调用以来捕获的），
它会立即返回。

仅当缓冲区为空或最新帧
已被上一次 `async_read` 调用消耗时，它才会阻塞至多 `timeout_ms`。

本质上，此方法返回最新的未消耗帧，必要时会等待
新帧在指定超时时间内到达。

用法：
- 非常适合控制环路，因为它能确保每个被处理的帧
都是新鲜的，从而有效地让你的循环与相机的 FPS 同步。
- 超时的常见原因包括：相机 FPS 极低、处理负载过重、
或相机已断开连接。
